# V0.1 工具链与默认模板对齐

## 四个参考模板

- React：`tsconfig.json` → `tsconfig.app.json` / `tsconfig.node.json`，Vite+ React 插件。
- Vue：Vue SFC、`@vue/tsconfig`、Node 类型配置、Vue 插件。
- NestJS：`apps/server` 采用默认模板 ESM、装饰器、Nest CLI、Module/Controller/Service、Vitest + Supertest E2E；业务 API 暂未开发。
- Tauri：`apps/desktop` 采用默认模板 Rust 工程、`src-tauri`、权限、窗口、图标，默认加载 React，`--config` 切换 Vue。

本轮不照搬与实际需求无关的模板 Demo、Router、Pinia；Tauri Rust 仅保留最小桌面壳，不注册模板示例 greet 或 opener 插件。

## 依赖基线

`pnpm-workspace.yaml` Catalog 统一所有第三方依赖版本；工作区内部依赖使用 `workspace:*`。TypeScript 6.0.3、Vite+ 1.5.0、Vitest 5.1.0 为本轮配置基线；不声称已经在用户本地环境成功解析和编译。

`pnpm-lock.yaml` 是旧版本锁文件，必须在开发者本机执行 `pnpm install` 并将变化单独审查、提交。不要手工伪造锁文件。

`vp test run` 运行根配置下的 Core、Runtime 与 NestJS 单测；NestJS E2E 通过服务目录独立 Vitest 配置运行。测试 API 统一从 `vite-plus/test` 导入。

NestJS 和 Tauri 的 Node 依赖统一由 pnpm Catalog 管理，Rust crate 独立由 Cargo.toml / Cargo.lock 管理（不属于 npm 依赖，不能放进 pnpm Catalog）。新版 pnpm 与 Cargo 锁文件尚待有联网工具链的 Windows 环境生成、审查。

## 模块边界

Studio / Runtime 共处 `apps/web-react` 或 `apps/web-vue`，但后者不反向依赖编辑器。Gateway 独立进程，浏览器不得直接连接 PLC / DCS。
