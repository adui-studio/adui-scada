## 一、可核实的仓库现状

- `TagStore.apply` 的 `TagValue.sequence` 是逐 Tag 严格增长的版本条件，**不是已承诺连续的传输事件编号**。目前 `5 → 7` 不直接证明丢包，也不证明完整性。
- Core 的 `sourceVerified` 是调用方传入的布尔字段；`generation` 只是本地订阅代次。两者均不构成网关身份、工程授权或网络消息真实性证明。
- `classifyTimelyNumericAlarmSample` 校验数值质量、时间格式和年龄；可信时钟的发行者、跨主机偏差与原始数据采集延迟**尚未确定**。
- `transitionAlarmState`、`replayAlarmEvents` 是纯状态工具；后者的数组位置序号不是持久化事件 ID。正式规则计算、报警持久化、确认授权和不可变审计尚未交付。
- 当前没有可信工业 Gateway 入口；模拟 SSE、React/Vue Runtime、Tauri 均不得用来证明生产来源可信。发布安全门禁继续 fail-closed。

## 二、D1～D5 推荐决策（全部待批准）

| 编号 | 推荐设计基线 | 必须拒绝的替代方式 | 尚需明确的实施参数 |
| --- | --- | --- | --- |
| **D1：身份及 Tag 授权** | Lab 第一阶段只做**进程内只读模拟入口**，不暴露 HTTP/网关端口、不产生正式报警事件；未来生产网关通过服务端可认证的机器身份（优先评估 mTLS）建立入口，服务端将该身份绑定工程/数据源/Tag 允许集，并按每次接入校验 | 客户端提交 `sourceVerified: true`、仅凭 IP/请求头/工程 ID、自签字符串、浏览器 OIDC 登录冒充网关认证 | mTLS 终止位置、受信代理范围、证书颁发/轮换/吊销、网关身份映射与权限存储 |
| **D2：时间权威** | 可信服务端在完成身份/授权与接收验证之后赋予候选 `serverTimestamp`，使用 UTC 毫秒格式；保留源时间为原始非授信字段。传输延迟与实际采集新鲜度需另有可核实的采样时效合同 | 接受请求体伪造的服务器时间、用客户端时钟、悄悄截断微秒或凭“刚收到”认定采集值未过期 | 最大时钟漂移、跨节点时间权威、源精度归一化方案、采样延迟上限及失同步处置 |
| **D3：序列域** | 保持现有 `TagValue.sequence` 单调语义；如需证明连续性，**另设**以网关身份和流代次限定的连续传输游标，独立持久化与校验 | 将 Tag 的 `5 → 7` 一律拒绝或一律视为无损；在不同网关/重启代次之间直接比较游标 | 游标粒度（源/流/Tag）、单调起点、容量/溢出、断电重启后是否持久化及覆盖范围 |
| **D4：缺口与恢复** | 只有协议明确保证完整性时才判定游标缺口；发生真实缺口、断流、认证撤销或无法证明的重复重放时停止**正式报警输入**，终止旧基线；显示快照与报警历史恢复分离 | 用最新快照补造断流期间触发/恢复事件；静默丢包、旧会话继续推送正式事件、无限缓存 | 可靠重放/确认水位、最大缓冲及背压、重同步策略、历史不完整的标记与保留期 |
| **D5：报警事件与确认** | 服务端在规则版本、可信候选及授权范围内决定触发/恢复；事件 ID、状态和审计采用一致的持久化事务；确认必须独立鉴权、并发保护并审计操作者 | 浏览器直接计算正式报警、把候选 READY 直接当事件、数组位置当事件 ID、前端自行确认或修补历史 | 阈值、死区、去抖、重触发、幂等键、确认 ACL、审计保留及失败审计路径 |

以上是**推荐方向**而非已经实现或批准的安全协议。即使维护者同意本 PR 合并，也不能将 D1～D5 自动标记为 Accepted。

## 三、分阶段准入建议

### S0 · 无网络、无业务写入的隔离模拟

使用显式隔离、受控注入的数据源研究 Tag 归属、时间标准化和独立传输完整性元数据。只允许单元测试及诊断结果，**不声称来源认证已完成，也不输出正式报警事件**。不新建开放端口，不触碰生产库、实际设备或已有业务工程。

### S1 · 身份认证和只读入口

只有 D1/D2 获批后才建立独立网关到服务端入口。服务端通过已验证的机器主体及 Tag 允许集做准入，忽略并拒绝网络负载中的“已核验”自称；信任代理的身份头必须在可信边界清理与重新签发。所有拒绝均不得写入有效报警候选。

### S2 · 序列完整性和可观察降级

只有 D3/D4 获批后才引入传输游标和跨重启恢复；版本号跳跃与传输缺口分别测试。不能证明遗漏期间的报警事件完整性时，明确记录**历史未知区间**，不把快照成功误认为已补齐历史。

### S3 · 服务端报警规则、事件与确认

只有 D5 获批且前面门禁满足后，才设计 Prisma 增量模型、隔离数据库事务和受保护 HTTP API。正式事件必须由后端生成、以持久化 ID 追踪，并可在确认与恢复并发时重放出一致状态。**不因有发布事务能力就默认获得报警确认权限**。

### S4 · 真实端到端验收

隔离 PostgreSQL、真实 OIDC/BFF、网关断流、React/Vue 对等、Windows/Docker、反向代理和完整 `ready` 分别验证。生产 PLC/DCS 仍不开放写入；工业现场上线必须另行安全评审。

## 四、安全不变量

- **I-01**：未建立可信且已授权的数据源主体，不得产生可用于正式报警的候选。模拟成功不等于工业身份认证。
- **I-02**：每条 Tag 必须在网关身份、数据源、工程与受控会话允许域内；错租户、错工程、错 Tag 全部拒绝，不能通过客户端字段修改范围。
- **I-03**：时间格式正确不等于采样时间可信；服务器接收时间无法替代被证明的源采集时效。
- **I-04**：`TagValue.sequence` 的合法跳号不得被误判为传输缺口；具备独立连续游标证据的真实缺口不得被忽略。
- **I-05**：断流、失效会话、已知事件缺口和无法恢复的历史空白不得自动生成触发、恢复、确认或伪造 GOOD 质量。
- **I-06**：报警业务事件与确认审计在可信服务端持久化；故障与并发不允许半提交、不允许客户端绕过授权。
- **I-07**：任何新增入口默认关闭。禁止设备写入、浏览器直连 PLC/DCS、在日志中打印凭据或工业网络敏感地址。

## 五、未来负向验收矩阵（均未执行）

| 测试 | 输入 / 故障 | 预期 |
| --- | --- | --- |
| T-01 | 未认证网关或伪造 `sourceVerified: true` | 拒绝；零正式事件 |
| T-02 | 有效网关身份但访问别的工程/Tag | 拒绝；不泄露跨域 Tag |
| T-03 | 可信代理外伪造客户端证书身份请求头 | 拒绝；不允许提升为可信来源 |
| T-04 | 证书过期/吊销或身份映射变更 | 停止旧会话，旧回调不能复活 |
| T-05 | 伪造服务端时间或时钟倒退、超过允许漂移 | 不信任请求时间；拒绝或暂停输入 |
| T-06 | 源采集已过期但网络到达时间很新 | 不冒充新鲜采集值 |
| T-07 | 合法 Tag 序列 `5 → 7`，无传输游标承诺 | 不擅自判定丢包，也不宣称历史完整 |
| T-08 | 独立连续游标承诺为 5、6、7，实收 5、7 | 识别真实缺口；停止正式报警输入 |
| T-09 | 网关重启后游标从零开始，新的已认证流代次 | 不跨代次误比较，也不复活旧回调 |
| T-10 | 断流期间阈值曾越界又恢复，重连仅获取正常快照 | 不伪造“从未报警”，需完整事件回放或标记未知 |
| T-11 | 背压导致记录溢出、队列超限或重放失败 | 可观察降级；不无声丢弃正式报警历史 |
| T-12 | 未授权主体尝试确认报警 | 默认拒绝；零状态变更 |
| T-13 | 两个主体并发确认/恢复、同幂等键重复提交 | 无重复成功事件或半提交；历史可复核 |
| T-14 | PostgreSQL 事务失败或会话撤权 | 原事件与状态一致；权限失效后不能提交 |
| T-15 | React/Vue 读取同一事件流及历史未知区间 | 展示一致；不得由任意前端独立决定正式报警 |
| T-16 | 配置开关缺失、未知认证协议或生产环境误连 | fail-closed；不开放 HTTP 接入或设备写入 |

T-01～T-16 是未来验收义务，不能把文档检查或 Core 单元测试当成它们的通过证据。
