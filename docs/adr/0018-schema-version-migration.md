# ADR-0018：工程 Schema 0.2.0 显式迁移与未知字段拒绝

- 状态：Proposed
- 日期：2026-11-10
- 关联需求：FR-013、FR-016、NFR-004
- 依赖：[ADR-0017](0017-node-grouping.md)

## 背景

第九批在预发布 `ScadaDocument 0.1.0` 中增加可选 `groupId`，新旧解析器对同一版本号的语义不一致。旧解析器可能丢弃未识别的结构字段，并在重新导出时静默损坏组合关系。必须通过新版本号与受限的显式迁移解决该问题。

## 决策

1. **目标版本**：`SCADA_SCHEMA_VERSION = "0.2.0"`；唯一已知历史版本是 `LEGACY_SCADA_SCHEMA_VERSION = "0.1.0"`。Schema 版本和 npm 包版本相互独立。
2. **内部严格解析**：`parseScadaDocument` 仅接收 `0.2.0`，供 Runtime、共享命令和文档快照使用，不在操作过程隐式迁移。
3. **专用迁移入口**：`migrateScadaDocument(input)` 只允许 `0.1.0` 或当前 `0.2.0`。旧版先校验，再以当前 Parser 二次校验；返回 `{ document, migratedFrom }`。未来版本、未知版本、无版本一律拒绝。
4. **严格结构字段**：根、页面、尺寸、节点、几何变换与 Tag 绑定条目实行白名单；未知字段不得悄悄删除。图元的 `props` 与 `rules` 延续安全 JSON 的值类型、长度、深度和危险键校验。
5. **数据保真**：原有页面/图元 ID、顺序、几何属性、静态属性、规则、Tag 绑定与合法 `groupId` 不改变。旧版未组合图元不添加空组合字段；所有新导出只有 `0.2.0`，不提供降级导出。
6. **原子性与双框架**：`DocumentEditor.loadDocument` 全部验证成功后才替换工程并重置历史，返回旧版本号供 Vue/React 显示中文提示；失败不改变当前编辑状态。两套界面不各自维护迁移逻辑。
7. **工业边界**：不增加设备写入、客户端 PLC/DCS 直连、服务端工程发布、数据采集或 Runtime 编辑命令。

## 风险和限制

- 之前 `0.1.0` 解析器可能会忽略未知结构字段；现在这种旧工程会显式报错，需由维护者确认字段含义，不能自动删除后继续。
- 旧版 `0.1.0` Parser 应因版本不匹配拒绝新版 `0.2.0`；尚未对所有历史二进制客户端做实际兼容测试，不承诺旧客户端可编辑或保存新工程。
- 当前只实现单段 `0.1.0 → 0.2.0`，不支持任意历史迁移链、版本协商、服务端持久化、冲突合并或正式发布。
- 尚未执行本批 Windows `pnpm run ready` 和 Vue/React 双向 JSON 验收；ADR 在验证前保持 Proposed。
