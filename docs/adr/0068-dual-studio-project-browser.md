# ADR-0068 · Vue/React Studio 内的受保护工程浏览与显式载入

- 状态：Proposed
- 日期：2026-11-16
- 验收：Windows 工程质量链与双端真实浏览器待执行

## 背景

PR #56 已合并有界 `GET /api/v1/projects`，但两个正式 Studio 尚无工程列表入口，用户只能按当前工程 ID 查询服务端历史或保存。浏览器草稿、服务器工程版本及 CAS 保存基线各自具有不同的生命周期；若在列表点击时直接替换当前画布或自动保存，可能覆盖未保存修改、混淆租户身份或损坏 IndexedDB 草稿。

## 决策

1. 在现有 React/Vue Studio 工具栏分别增加独立的“工程管理”弹层，不重构导航或改变 Runtime。Vue 使用 `.vue` Composition API，React 使用现有 TSX；布局和深色品牌 Token 沿用共享 `@adui/tailwind` 样式，并保持完整画布不受弹层影响。
2. 工程摘要、分页规则在框架无关 `@adui/scada-api-client` 的 `StudioProjectBrowser` 中维护，每页 10 项；首次展开、刷新和翻页均经现有 `listProjects` 及服务端 ACL。首末页、空终页、网络错误重试和重复并发点击使用相同状态机。读取被拒绝（401/403/404）时清除会话中上次成功的工程摘要及游标，不持久化列表。
3. 只有人工点击“打开”才按摘要的修订号调用 `StudioServerProjectSession.readVersion`；它重新核验可信登录、目标快照的 SHA-256 与工程 ID、当前服务端水位。水位不同或编辑工程已在等待时切换则拒绝，不建立 CAS 基线、不覆盖画布；绝不将列表摘要的 headRevision 直接当作保存基线。
4. 只有确认替换当前画布后，先停止正在进行的 IndexedDB 自动保存，再调用现有 `DocumentEditor.loadDocument` 清空撤销历史，并调用 `acceptLoadedVersion` 建立主体绑定的 CAS 基线。**不删除、改写或自动恢复任何 IndexedDB 草稿和本地历史**；跨工程切换后只刷新对应草稿的可用性与订阅，不继承前一个工程的版本显示。
5. 保持服务端 OIDC 默认关闭、无生产密钥、新数据库模型/迁移和工业设备写入能力；本批不是独立工程中心、工程发布审批/回滚或设备监控功能。

## 验证与未解决问题

新增共享分页会话单元测试覆盖前后翻页、末页、失败重试、并发及权限重置。真实 React/Vue 浏览器需要分别核对授权列表、各自打开安全、人工取消、服务端水位变化、CAS 基线和本地草稿不变，且在两个分辨率下不得影响 16:9 画布和布局；未在维护者 Windows 执行前全部标记待验收。

后续正式工程中心如需搜索、按最近更新时间排序、删除/归档和团队权限管理，必须独立定义服务端可审计契约与 UI。不能将本次只读工程浏览解释为所有工程管理能力已交付。
