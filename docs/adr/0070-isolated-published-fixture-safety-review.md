# ADR-0070：独立已发布 Lab 测试夹具的准入、正式发布路径与安全验收

- 状态：Proposed
- 审批：待维护者与工业安全专项评审，**未授权实施**
- 日期：2026-11-22
- 关联：[Issue #126](https://github.com/adui-studio/adui-scada/issues/126)、FR-008、FR-013、FR-014、FR-016、NFR-002、NFR-003、NFR-004、NFR-006
- 前置：[ADR-0069](0069-release-pointer-atomic-publication-design.md)、[正式发布事务评审矩阵](../RELEASE_TRANSACTION_REVIEW.md)
- 涉及当前代码：`apps/server/src/projects/project-release-safety-gate.ts`、`apps/server/src/projects/prisma-project-release-store.ts`、`scripts/discover-published-fixture-readonly.mjs`
- 约束：本 ADR 仅提出**流程及安全门禁要求**。不引入发布代码、宽松替身、环境变量放行、数据库变更或工业设备写入；本 ADR 或其 Draft PR 获得合并也**不等于**准许真实发布、撤权或生产启用。

## 1. 决策背景及可核实证据

D5b7b～D5b7f 的元数据分类、PostgreSQL 只读审查、原 D5b1 基线保护、目标全量 ACL 和无 ID 发现已陆续通过维护者 Windows 离线验收并合并。维护者在本机可信 Lab 实际执行 D5b7f，结果为：

```text
D5b7f 未发现符合命名空间、发布代次和读取权限的独立候选。
D5b7f 真实只读发现退出码：1
```

这是符合 `d5b7b-published-%` 专用前缀、可信主体 `release:read`、非零发布代次和非空指针等**综合筛选条件**的 `NOT_FOUND`。它不证明数据库没有其他工程，也不证明发布功能失效。当前未发现经正式流程发布的独立 Lab 工程，更没有真实不可变快照、`200/RELEASED` 或 `verified → denied` 的证据。

当前已合并的正式发布仓储路径执行锁内可信会话、`release:publish`、双 CAS、不可变快照 SHA-256 和 Core 预检，然后调用 `ProjectReleaseSafetyGate.assertReady()`。该门禁目前**无条件抛出** `ProjectReleaseGateUnavailableError`，因此正式发布事务不会提交成功的事件和指针。这是有意保留的安全拒绝，不应通过测试用 SQL 伪造已发布状态。

## 2. 明确不采用的捷径

1. **不允许**直接 INSERT/UPDATE 发布指针、发布事件、版本摘要，或修改既有 Prisma 迁移 / 约束以制造 `RELEASED`。
2. **不允许**通过环境变量、请求字段、仅测试用 Provider、启动脚本 Monkey Patch、无条件 Mock 或“只有本机才放行”的额外路径绕过 `ProjectReleaseSafetyGate`。
3. **不允许**将 D5b1 原未发布工程、D5b4 已撤权工程、现有真实业务工程或合成 `RELEASED_METADATA_ONLY` 样例升级为可撤权的已发布夹具。
4. **不允许**为达到测试结果而临时授予所有人 `release:publish`、`release:read` 或从 `version:append` 自动继承权限。
5. **不允许**客户端直连 PLC/DCS、引入通用设备写入，或将模拟 Tag 质量冒充现场 `GOOD`。

## 3. Proposed 决策：正式门禁完成之后才能生成真实夹具

核心决策候选为：**唯一合法的已发布夹具来自经过独立安全验收的正式发布服务与正式 API**。不能先造夹具、后补安全门禁。

- **安全门禁实现本身**必须作为独立架构/工业安全工作包，经源码与测试评审后才能替换当前固定拒绝行为。它应在事务内检查可信项目、完整快照、有效且独立的发布权限、运行引擎/资源兼容性、Tag 绑定合法性、数据源白名单、工业只读策略以及审计完整性。任何未知/缺失/失效均拒绝。不可用资源与非法质量不得自动降级为允许发布。
- **可接受的候选数据**应是单独创建的最小静态 SVG Lab 工程，不含任意脚本、外部资源依赖、未知图元、未审核 Tag 绑定或设备连接；“静态无绑定是否满足安全门禁”仍由正式安全规则判定，**不能仅因没有 Tag 就默认通过**。
- **测试库与业务库隔离**：先在已明确验证的独立测试数据库完成事务、并发及故障注入；需要在既有可信 `adui_scada` 本机 Lab 中验证时，须再次确认库的真实来源、已有 D5b1/D5b4 状态与可恢复备份。不得把 `adui_scada_test` 的测试授权自动迁移到 `adui_scada`，也不把 `adui_scada` 视作生产写入许可。
- **正式发布路径不变**：必须经可信 OIDC/BFF、同源 CSRF/Origin、安全权限和版本 CAS，由服务端读取当前已保存 head，执行 `POST /api/v1/projects/:projectId/releases`；不允许通过直接 DB 写入模拟 HTTP 成功。发布事件、指针和代次必须在一个 PostgreSQL 事务中原子提交。
- **工程命名与唯一性**：只有未来明确批准创建的随机 UUIDv4 专用工程使用 `d5b7b-published-<UUIDv4>` 命名空间。该命名本身不代表信任，实际权限、合法发布来源和审计必须独立验证。不得复用 D5b1/D5b4，也不运行泛用工程枚举。

上述决定仍为 Proposed。**在真正实现并验收门禁之前，本 ADR 不支持任何创建、授权、发布或撤权写操作。**

## 4. 审批与职责分离

- **S0 · 设计评审**：维护者审查本 ADR 与 ADR-0069/R-01～R-08 的一致性，工业安全负责人确认只读资源/Tag/数据源规则，明确执行责任人。**未满足时**：保留 Proposed，`assertReady` 固定拒绝。

- **S1 · 门禁实现评审**：单独 Draft PR、`@adui-dev` 指派；正式门禁实际代码、默认拒绝证明、权限/事务/工业安全负向测试及双框架影响分析。**未满足时**：不合并可放行的实现。

- **S2 · 环境与夹具准备审批**：明确本机隔离环境与库名、允许的专用新工程范围、可信测试主体及独立 `release:publish` / `release:read` 来源、备份/恢复负责人及有效窗口。**未满足时**：不连接写库、不创建工程、不增权。

- **S3 · 首次真实发布单次授权**：S1 和 S2 验收完毕；显式批准具体工程 ID、当前版本、发布预检证据、正式发布 API、幂等键与预期代次；操作时再复核。**未满足时**：不调用发布 POST。

- **S4 · 已发布只读验收**：成功提交的独立发布事件、指针及不可变快照真实 SHA-256，可信身份的真实 HTTP `200/RELEASED` 和两端 Runtime 画面。**未满足时**：不宣称 `verified`。

- **S5 · 单项撤权专项审批**：单独批准测试主体、一次性撤销 `release:read` 的范围/时点、备份与恢复方案、数据保留策略、双框架浏览器只读监视。**未满足时**：不执行 ACL 删除/恢复。

- **S6 · 审计与结束**：末次只读核对、失败记录、基线不变、操作审计以及归档/隔离方案；不删除已提交不可变事件。**未满足时**：不关闭 Issue #126。

审批应分别记录：**批准者、目标、窗口、可执行动作、禁止动作、应急终止条件和恢复责任人**。同意设计、PR 合并、通过 `ready` 均不自动替代 S2～S5 具体授权。

## 5. 合法夹具生命周期候选

1. **准备前**：固定读取并保存原 D5b1、D5b4 的脱敏基线；通过可信 OIDC 身份检查、迁移状态及专用 Lab 连接校验。既有不可变版本和审计不得被清理或改写。
2. **创建**：仅在 S2 另行批准后，经现有正式同源工程创建 API 创建**一份新的**随机专用工程，并保存最小兼容静态快照。未经授权不能执行任何数据库写入。
3. **授权**：仅在明确授权后为专用工程主体添加必要的、可审计的**独立**发布与读取权限，必须先核验不存在额外主体或多余权限。没有广义“管理员自动通过”。
4. **正式发布**：仅在 S1 门禁可用且 S3 批准后，经已存在的正式 API 发起一次真实发布。事务失败时必须保留 `releaseGeneration=0`、空发布指针、零成功事件；不能直接修库重试。网络响应不确定时先执行只读审计，不能盲目重发。
5. **发布后核验**：以实际受保护读取 API 和版本快照 SHA-256 为准，关联事件、代次、租户工程、快照及 HTTP `no-store`；React/Vue 独立观察同一已发布画面，实际 Tag 质量仍按真实状态呈现。
6. **撤权**：只有 S5 获准，才允许使用受控的单项 `release:read` 撤销事务。真实 404 后验证隐藏/重显、迟到 200 不复活旧内容、草稿与 CAS 不漂移，以及原 D5b1/D5b4 不变。
7. **结束和恢复**：明确专用夹具最后应保留、隔离或按独立授权处置。发布事件与不可变版本**不能因为测试结束而直接删改**；若需要恢复读取权限，须另获针对该项目的一次性授权与复核。禁止自动修改原 D5b1/D5b4、自动回填指针或泛用数据库清理。

## 6. 失败分支与证据级别

- **无候选**：D5b7f 返回 `NOT_FOUND`（退出码 1）是正常拒绝，不自动启动创建或发布。
- **多个候选**：`AMBIGUOUS`；不任取第一条，不输出任意 ID，也不改变权限。
- **元数据一致**：`RELEASED_METADATA_ONLY` 仅表示被核查的数据库元数据一致，不是快照真实 `verified`。
- **真实快照与 HTTP**：只有服务端受控读取重新校验并实际呈现 `200/RELEASED`，才可记录发布读取层面的真实证据，尚不等于撤权通过。
- **撤权后拒绝**：只接受真实 HTTP 状态和客户端画面清空/草稿不变等原始观察；模拟 404、合成快照、纯单测不得替代。
- **失败后事务与审计**：如果出现不明提交状态，先安全停止并执行只读取证；未经批准不得重试写事务或手工修复历史。记录脱敏状态、时间、分支 HEAD、命令及退出码，不记录原始工程正文、Cookie、Token 或密码。
- **任何生产资源疑似被触及**：立即停止后续写入与浏览器实验，保留可审计证据，交维护者/工业安全负责人处理。

## 7. 未来测试矩阵（全部待实施、不能伪称已通过）

- **LF-01**：非隔离库、生产模式、未可信主体、不完整迁移。**预期**：在任何工程写入之前拒绝。

- **LF-02**：安全门禁实现遇到未知图元、未审查 Tag、外部资源、无效质量/数据源。**预期**：一律拒绝，不发生成功发布事件。

- **LF-03**：`release:publish` 缺失或会话失效、CSRF/Origin 错误。**预期**：无写入，权限不从编辑 ACL 继承。

- **LF-04**：并发版本追加/重复发布、过期 head/代次、幂等冲突。**预期**：不发生半提交、代次冲突不丢失。

- **LF-05**：事件插入/指针更新/网络提交结果不明。**预期**：数据库快照和事件原子一致，未知结果只读复核。

- **LF-06**：非法摘要、跨租户工程事件、旧指针或 Schema 不兼容。**预期**：拒绝已发布读取，不向浏览器返回正文。

- **LF-07**：未发布独立夹具和已发布真实夹具的双框架对照。**预期**：只能由真正发布指针产生 `RELEASED`。

- **LF-08**：撤权前真实 `200/RELEASED`、撤权后真实 `404/denied`。**预期**：两端均清空发布画面，不伪造请求。

- **LF-09**：隐藏/重显、断线与迟到 200、IndexedDB 草稿与 CAS。**预期**：撤权 404 不被旧响应覆盖，草稿/画布无漂移。

- **LF-10**：测试前后 D5b1/D5b4 基线及目标权限/审计记录。**预期**：原资产不变，目标变更限于每次明确审批。

- **LF-11**：失败注入与资源回收。**预期**：只读连接、会话、锁、浏览器和日志按约定清理。

- **LF-12**：归档或恢复决策。**预期**：有审批和审计，不删改真实发布事件与历史快照。

测试分层：静态文档评审 → 门禁/事务纯单测 → 独立 `adui_scada_test` 真实 PostgreSQL → 受控 Lab 正式 HTTP 发布/读取 → Keycloak/HTTPS 双框架 → 单独批准的动态撤权。任何前置失败都停止，不跨层推断通过。
