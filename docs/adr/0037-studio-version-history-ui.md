# ADR-0037：Vue/React Studio 本地工程历史版本管理界面

- 状态：Proposed
- 日期：2026-11-11
- 关联需求：FR-002、FR-008、FR-013、NFR-004、NFR-006
- 依赖：[ADR-0035](0035-project-validation-snapshot.md)、[ADR-0036](0036-local-version-history.md)

## 背景

V0.3 第三批已交付框架无关版本仓储接口与独立 IndexedDB 本地历史库，但 Vue/React Studio 无法操作历史记录。本批需要在不改变工程 Schema、现有草稿存储、工业设备连接及发布权限的情况下，为两个正式前端提供等价的本地版本创建、查询、比较和载入操作。

## 决策

1. **顶部独立历史菜单。** 在两套 Studio 的“文件与草稿”旁增加“版本历史”菜单。使用现有工作台控件风格、共享 `@adui/tailwind/studio.css`；按工程 ID 隔离列表，打开菜单与“刷新”时读取当前工程的本地历史。单页 10 项，按 `revision` 倒序，游标读取更早历史；显示修订号、创建时间与摘要短码。
2. **显式创建历史。** 点击“创建快照”时捕获当前编辑器文档，通过 `getHeadRevision + append` 创建只追加 SHA-256 版本。版本号由 Dexie CAS 事务分配，冲突明确中文提示；既有草稿、自动保存规则及 Studio 撤销历史均不发生变化。快照存储于当前浏览器 Origin，**不是服务端备份或正式发布**。
3. **共享内容比较。** `packages/core/src/project-version-compare.ts` 新增 `compareProjectDocuments`，对两份当前 Schema 文档重新严格校验并确认同一工程，递归比较 JSON 内容（对象键顺序不影响结果；页面与节点数组顺序需要一致）。返回 `sameContent` 和双方的页面、图元与 Tag 绑定数量；不包含工业实时 Tag 值，也不执行规则或脚本。查看差异**只读取与展示**，不影响当前编辑器。
4. **确认后载入。** 点击历史版本“载入”会重新从版本仓储读取并校验 SHA-256。用户必须确认“替换当前画面、清空撤销历史、未保存内容可能丢失”，取消即不改变工程与自动保存状态。确认后先 `pauseAutoSave` 等待已开始的草稿事务完成，再调用现有 `DocumentEditor.loadDocument`，清理画布拖动/图层搜索等临时状态，刷新草稿可用状态；**不写 Dexie 草稿、不自动创建历史版本、不修改发布指针**。
5. **并发与错误处理。** 浏览器 UI 的异步历史操作使用忙碌门闩，载入历史期间复用现有草稿操作门闩；JSON 导入若已有工程操作则明确拒绝。工程 ID 在异步过程中变化时，不将历史记录加载到其他工程。数据库访问故障、版本丢失、SHA-256 不匹配、容量和 WebCrypto 不可用均显示中文错误；保持现有画面。
6. **不交付的能力。** 此菜单只是本地手动历史快照，不提供资源包差异、图元逐项 diff、服务端鉴权、发布审批、审计、回滚、正式 Runtime 快照指针、云备份或 PLC/DCS 设备写入。不同 Origin（例如 React 5173 和 Vue 5174）本地历史不自动共享，跨框架工程仍通过现有受校验 JSON 互导。

## 质量与验收

- Core 新增 4 项比较单测：一致、坐标变化、对象键顺序、不合法/跨工程。
- 新增 `pnpm run test:versions`：隔离 Chrome/Edge 中分别进入 React/Vue Studio，真实点击创建版本、修改图元、查看差异、取消载入、确认载入和再次创建版本，并检查 JSON 内容一致性与倒序历史列表。
- 旧 `test:interop` / `test:browser` 与 `ready` 均保持独立入口；建议回归三项浏览器验证及完整质量链。
- 新版本分支尚未在维护者 Windows 实测全部命令。本 ADR 保持 Proposed，不把本地功能等同正式 FR-008 发布完成。
