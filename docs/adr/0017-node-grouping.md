# ADR-0017：平面图元组合与工程 JSON 兼容性

- 状态：Proposed
- 日期：2026-11-10
- 关联需求：FR-005、FR-013、NFR-004
- 依赖：[ADR-0009](0009-studio-editor-foundation.md)、[ADR-0011](0011-editor-canvas-operations.md)、[ADR-0016](0016-aspect-ratio-resize.md)

## 背景

Vue 和 React Studio 已有多选、整体拖动、八方向缩放与本地 JSON 草稿，但选择状态仅存在于会话中，导出工程后不能恢复临时组合。正式 SVG 图元分组树将牵涉节点父子层级、坐标系、重排、缩放、序列化与 Runtime 渲染，超出 V0.2 当前开发阶段。需要先支持多图元「组合/解组」这一常见编辑能力，同时维护安全和工程互通。

## 决策

1. **逻辑平面组合**：`ScadaNode` 上增加可选 `groupId?: string`。同一组合的节点维持原有平铺顺序、世界坐标及 Tag 绑定；不引入嵌套 `<g>`、新的图元类型或父级 transform。没有组合时字段必须省略。
2. **校验和边界**：在现有 `parseScadaDocument` 校验组 ID 只包含安全 ASCII 字符、同一组合至少两位成员、组合 ID 与任何页面/图元 ID 不重名、组员不得跨页面。组合数量因图元 2000 上限受到限制。非法工程原子拒绝导入，克隆后不共享输入对象。
3. **编辑器命令**：`DocumentEditor.groupSelected()` 将至少两个均未组合的节点设为一个新 `group-N`，`ungroupSelected()` 清除所选组合 ID。二者各自形成一条可撤销历史，不改变节点几何与绑定；组合 ID 为本工程唯一、不依赖系统时间的递增可用序号。
4. **完整组员选择**：点击任一组员，选中整个组合。Shift 切换、框选及全选展开同组节点。新增轻量 `grouping.ts` 纯函数供 `withNodesTranslated` 和 `resolveDragSnap` 同步扩展组员，解决单成员位移导致预览与最终提交不一致。组合删除也以全组为单位。
5. **防止内部布局意外破坏**：组合状态下禁用单个图元的几何和文案修改，逐成员对齐需要先解组。图层层序仍保留现有平铺节点顺序语义，跨层散落的组员不会自动重新排列为连续层。Vue/React 仅增添操作入口及组合标识，不直接修改工程 Schema。
6. **仅本地组态草稿**：不增加真实 PLC/DCS 连接、设备写入、WebSocket 设备控制、服务端持久化或运行时脚本；Runtime 继续逐节点读取现有图元和 Tag。

## Schema 兼容性决定和风险

目前 `SCADA_SCHEMA_VERSION` 仍为 `0.1.0`，本次在该预发布工程结构中增加**可选字段**，保证**新版解析器可以读取旧文档**且 Vue/React 当前版本可相互导入导出。**旧版解析器只复制白名单字段，可能丢弃 `groupId`；因此旧客户端打开再保存新版组合工程将造成组合丢失。**旧客户端写回不在本批兼容承诺范围内。

正式工程存储、生产发布或长期兼容前，必须评估新 Schema 版本与 `0.1.0` → 新版迁移，并补充跨版本拒绝降级/警告机制；不能把新增字段视作完整的双向版本兼容。当前这项决策在 V0.2 原型中为 Proposed，待维护者明确接受后再演进。

## 本批不实现

- 嵌套/跨页面组合、组合整体缩放/旋转、组合统一包围框、单独修改组员位置、复杂图层整组连续排序。
- 服务端工程保存、发布回滚、真实协议和工业现场设备控制。
- 旧客户端往返或跨版本工程迁移及正式兼容性保证。

待 `pnpm run ready` 与 React/Vue 双向工程/交互验收通过后再评估是否接受本 ADR 与合并分支。
