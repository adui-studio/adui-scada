# ADR-0023：页面复制、排序与跨页面图元复制

- 状态：Proposed
- 日期：2026-11-10
- 关联需求：FR-002、FR-005、FR-006、FR-013、NFR-004、NFR-006
- 关联文档：[ADR-0022](0022-multi-page-editor-scope.md)、[V0.2 Studio](../V0.2_STUDIO.md)

## 背景

`ScadaDocument 0.2.0` 使用 `pages[]` 表示页面顺序，并要求页面 ID、图元 ID、组合 ID 全工程唯一。已有 `DocumentEditor` 支持页面管理和跨页面撤销，但直接复制原图元/组合 ID 会导致严格工程 Parser 拒绝，或产生跨页面组合引用错误。

## 决策

1. 页面复制使用 `DocumentEditor.duplicatePage(pageId?)`，默认当前页面，紧邻源页插入副本并激活新页。保留画布大小、图元数量与顺序、几何、Tag 绑定、属性及规则，副本名称追加「 副本」，限制在既有 256 字符长度内。
2. 复制过程使用全工程占用 ID 集，为新页面分配 `page-N`、新图元分配 `node-N`、新组合分配 `group-N`，同一旧组合在副本内映射为同一新组。源对象不修改；校验成功后以一条编辑命令原子提交。
3. `movePage(pageId, direction)` 仅将指定页面与前一个或后一个位置交换，保留原始页面和图元对象内容。边界位置移动返回 `false`，不增加历史记录；有效变更可撤销/重做。
4. `copySelectedToPage(targetPageId)` 只允许复制到其他已有页面，不删除源图元、不改变当前编辑页面和选中状态。对选中组合自动包含所有成员；组 ID 全部重映射，Tag ID 不变。复制顺序保持源页的图元排列顺序，副本追加到目标页末尾。
5. 跨页面复制以选中内容的非旋转矩形包围盒判断目标画布能否容纳。若能容纳但靠近画布外侧，则将所有副本作**同一平移**，保持相对位置与几何尺寸；若整体无法容纳则原子拒绝，不擅自缩放、裁切或拆散组合。
6. 新增操作沿用 `DocumentEditor` 当前的整文档撤销/重做和 `parseScadaDocument` 原子验证；页面上限 100、全工程图元上限 2000，以及 Schema 字段白名单维持不变。

## 持久化与 Runtime 的关系

- 复制/排序均修改整份工程 JSON，纳入已有 Dexie IndexedDB 草稿手动保存和按需自动保存；页面切换本身仍不产生修改。默认关闭自动保存，恢复仍需用户确认。
- 工程版本继续是 `ScadaDocument 0.2.0`，不新增 `clipboard`、`activePageId` 或隐式脚本。跨框架复制行为完全由共享 Core 驱动，Vue/React 只负责操作入口。
- **页面排序会改变 `pages[0]`**，因此现有只读 Runtime 若未指定页面，默认预览页面也会随顺序变化。这是目前模型的明确行为，未来如需独立设置启动页，应通过后续需求和 Schema 设计处理，不能本批擅自添加。
- 复制不代表跨项目或跨浏览器 Origin 共享；工业数据采集、Gateway、Tag 类型映射及设备写入均不在范围内。不得将本地草稿视为服务端备份或已发布工程。

## 验证要求

共享 Core 测试覆盖页面和图元/组合 ID 重映射、源内容不变、Tag 与属性保留、页面交换与撤销、非法目标和容量限制、不同画布整体平移、组合不可拆散、JSON 往返。维护者必须在 Windows 执行 `pnpm run ready`，再分别验收 Vue/React 对等的复制、排序及 IndexedDB 草稿往返。静态代码提交不等于已完成运行或工业现场验证。
