# ADR-0026：精确图层排序、组合连续移动与锁定保护

- 状态：Proposed
- 日期：2026-11-11
- 关联需求：FR-005、FR-006、FR-013、NFR-004、NFR-006
- 参考：[ADR-0022](0022-multi-page-editor-scope.md)、[ADR-0023](0023-page-copy-and-reordering.md)、[ADR-0025](0025-node-lock-visibility.md)

## 背景

现有 `DocumentEditor.reorderSelected` 支持置顶、置底和逐层调整，但旧组合可能在 `pages[].nodes` 中不连续。分别移动组员会造成视觉层序分离，且图层列表原本按文档从底层到顶层显示，缺少精准插入目标与可视拖放提示。

## 决策

1. `ScadaDocument 0.2.0` 中同一页面的 `nodes[]` 顺序是唯一的图层事实：**越靠后越在上层**。不增加 `zIndex`、新字段或独立排序表，不改变 Runtime SVG 的输出契约。
2. 共享 `DocumentEditor.moveLayer(sourceNodeId, targetNodeId, "before" | "after")` 定位当前页的源图元和目标图元。若源图元已分组，则完整提取所有成员，按原来相对顺序作为**连续块**插回同页；目标若已分组，则插入其首个成员之前或最后一个成员之后，避免把移动源插入该组合成员之间。
3. 源和目标同属一个组合时不产生修改或撤销历史；已相邻且没有变化时返回 `false`。仅成功排序提交一条可撤销/重做命令，持久工程只发生 `nodes[]` 顺序变化，Tag、规则、几何、锁定/隐藏状态、组 ID 和页面 ID 均不修改。
4. 锁定保护覆盖直接与间接修改：禁止拖动任何已锁定图元或含已锁定成员的组合；若其他图元移动后导致任意已锁定图元的**数组索引**改变，同样原子拒绝，不修改工程和历史。排序基于共享 Core 校验，不依赖 UI 按钮状态。
5. 旧 `reorderSelected` 四个按钮保留原接口；当选中恰好是一个完整组合时，复用精确插入逻辑实现连续整体移动。其他未组合多选继续保留既有上移/下移/置顶/置底语义，减少回归影响。
6. Vue/React 图层列表按 `nodes[]` 逆序展示，最上层显示在顶部。支持同页原生 HTML5 拖拽，目标行上半区域表示移动到目标**上方**（数组 `after`），下半区域表示下方（数组 `before`），并用高亮线提示插入位置；源与目标不从外部拖放数据解析，仅使用编辑会话内记录的图元 ID 和页面 ID。
7. 两套 Studio 同时提供无需拖拽的「目标图元 + 插入上方/下方 + 移动到指定层」操作区。通过按钮或拖拽调用同一共享 Core 命令；切换页面清理拖动状态。混合多选时禁用精确移动按钮，避免不明确的批量插入语义，组合全选仍允许整体移动。

## 兼容性与工业安全

- 保留 `ScadaDocument 0.2.0`、JSON 双框架互通、Dexie IndexedDB 整工程草稿和既有撤销历史；图层改变属于工程编辑，可按照现有手动/按需自动保存持久化，单纯拖拽悬停不修改工程。
- 隐藏图元仍保留在图层列表中并可排序（若未锁定），再次显示时按新图层顺序渲染。锁定只是 Studio 防误操作，不代表设备权限，也不影响 Runtime 的 Tag 质量或工业只读边界。
- 旧文档中非连续的组合成员仅在**该组合被移动时**整理为连续块；其他未移动组合不作无关自动重排。目标组合可能原本不连续，插入只使用其首/末成员作为边界，不擅自改变目标组的其他成员层序。
- 本批不实现跨页面拖放、外部资源拖入、跨应用剪贴板、工业设备写入或正式发布。

## 验证

Core 测试覆盖精确前后插入、无变化原子性、组合源移动连续性、组合目标边界、原四个排序按钮兼容、锁定源和间接锁定位置保护、隐藏状态、跨页隔离、撤销/重做及工程 JSON 往返。维护者需执行完整 `pnpm run ready`，人工验收 Vue/React 拖放位置、鼠标/按钮操作和 Dexie 草稿恢复。本批 Draft PR 未经授权不得合并。
