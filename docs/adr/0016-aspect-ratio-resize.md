# ADR-0016：Shift 保持图元宽高比缩放

- 状态：Proposed
- 日期：2026-11-10
- 关联需求：FR-005、FR-013、NFR-004
- 依赖：[ADR-0015](0015-eight-direction-resize.md)

## 背景

已有八方向缩放控制点，但四角可独立改变宽高、四边中点只能改变一个尺寸，不能快速按原始比例整体放大或缩小；工业组态中保持泵、水箱等图元视觉比例是常见需求。Vue/React 不能分别实现不同的数学规则。

## 决策

1. 扩展共享 Core 纯函数 `resolveResizeTransform(transform, handle, dx, dy, lockAspectRatio = false)`。第五参数默认关闭以保持既有 TypeScript API 的四参数调用行为；仅由两套 Studio 的缩放指针事件传入 `event.shiftKey`。
2. 将世界 Pointer 位移逆旋转至图元局部空间。四角手柄比较相对宽度变化 `horizontal × localDx / width` 和相对高度变化 `vertical × localDy / height` 的绝对值，选择变化较大的轴决定一个统一的缩放因子。中点手柄直接使用自身主轴。
3. 按原尺寸乘同一缩放因子计算宽高；依据旧的角/边中点方向系数计算中心偏移，再旋转回世界空间，保持旋转后的对侧角点/边中点固定。中点从边缘缩放时另一轴以中心对称变化，独立四角逻辑不回退。
4. 比例为原始宽高比而非 1:1。按已有两位小数舍入，因此宽高比允许极小量化误差；无位移/未改变尺寸保留原高精度数值。非法、非正因子与尺寸下限、页面边界继续由现有 Core 拒绝，并保持不可变预览和单次撤销历史。
5. 原旋转控制点的 Shift+15° 吸附不受影响；本次不增加第三方依赖、Schema 字段或工业数据写入通道。

## 风险和取舍

- 角点在拖动两个轴方向不一致时，主导轴取相对幅度更大者，避免斜向拖动比例破坏；与某些 CAD 软件的投影细节可能不同，需维护者实际体验验证。
- 当前控制点预览由 PointerMove 驱动，单独按下/松开 Shift 但鼠标静止时未立即重新计算，发生下次 PointerMove/PointerUp 才生效。
- 仍沿用未旋转布局矩形的画布边界约束，不执行旋转后像素级裁切、从中心等比例缩放或成组缩放。
- 改动前需要检查图元原尺寸已由 Schema 验证为有限、正数；后端持久化、工程发布和工业现场设备控制不属于本批。

状态待维护者在 Windows 运行 `pnpm run ready`、Vue/React 双向工程与交互验收后，再评估 ADR 的接受与功能合并。
