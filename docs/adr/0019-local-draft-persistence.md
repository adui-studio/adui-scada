# ADR-0019：Studio 工程草稿浏览器本地保存与显式恢复

- 状态：Proposed
- 日期：2026-11-10
- 关联需求：FR-002、FR-013、FR-016、NFR-004、NFR-006
- 相关决策：[ADR-0018](0018-schema-version-migration.md)

## 背景

V0.2 Studio 目前仅提供 JSON 文件导入与导出，刷新页面后编辑器重新载入演示工程，尚无草稿持久化。正式工程服务端保存、发布和权限模型尚未建设。需要先建立可测试、可控的浏览器本地草稿能力，防止未导出草稿只能留在当前编辑会话中，同时不能把不可信草稿静默加载到运行时或覆盖当前工程。

## 决策

1. **当前范围：手动保存、手动恢复和手动清除**。不自动保存，不在启动时自动恢复或覆盖演示工程；恢复、覆盖已保存草稿和清除都需操作员确认。当前编辑器可继续使用原有 JSON 导入、导出功能。
2. **共享无框架依赖的存储逻辑**：在 `packages/core/src/local-draft.ts` 提供 `LocalDraftStorage` 接口与 `saveLocalDraft`、`readLocalDraft`、`hasLocalDraft`、`clearLocalDraft`。Vue/React 仅提供 `window.localStorage` 适配及相同的中文操作反馈。测试用内存模拟存储；Core 不引入浏览器依赖。
3. **按工程隔离**：稳定键为 `adui-scada:studio:draft:<projectId>`，仅操作当前工程的记录；不同工程 ID 互不覆盖。同一浏览器 Origin 内可访问同一键，**不同端口、域名或桌面 Origin 的存储不保证互通**，跨框架工程交换仍以 `0.2.0` JSON 为准。
4. **持久化格式与安全**：存储包裹层独立声明 `formatVersion: 1`、ISO `savedAt` 和当前 `ScadaDocument 0.2.0`；先使用 `parseScadaDocument` 验证，再序列化写入。读取严格校验包裹层、版本、时间、工程 ID 和文档本体；UTF-8 文本总长不得超过 **2 MiB**。不执行表达式、脚本或不可信代码。
5. **失败与覆盖保护**：存储权限不足、空间不足、格式损坏、旧/未来版本和项目不匹配均返回中文错误；读取失败**不修改当前 Editor**，且不删除原始存储记录，以允许人工诊断。写入失败不主动清除旧草稿；清除操作仅移除指定工程的本地记录，不删除当前编辑会话。真正恢复时调用已有原子 `DocumentEditor.loadDocument`，成功后清空撤销历史。
6. **不混淆草稿和发布**：本地存储只用于当前浏览器/Origin 的临时草稿，**不保证备份、跨设备迁移或永久保存**。浏览器清除网站数据/隐身模式可能丢失记录；本地存储未加密，不能保存密钥、设备密码或其他敏感工业配置。重要工程必须另行导出 JSON 备份。
7. **工业安全边界**：不增加服务端工程写入、用户权限、WebSocket 控制、客户端直接连接 PLC/DCS 或任何工业设备写入；只读 Runtime 不读取 Studio 本地草稿。

## 取舍与后续

- 当前不实现自动保存、历史快照、浏览器多标签页并发冲突锁、加密存储、跨 Origin 同步、IndexedDB、服务端草稿 API、正式发布和回滚；这些必须后续设计并分别验收。
- 保存时由两套 UI 以原生确认对话框提示覆盖已有记录，恢复时明确告知将替换当前画面与清空撤销历史；失败保留当前画面。
- 仅使用既有浏览器 `localStorage` 和 TypeScript，不增加外部依赖或修改工程 Schema。需要 Windows 自动化质量链、Vue/React 页面刷新恢复、损坏记录及安全边界人工验收之后再接受此 ADR。

## 第十二批后续方案

[ADR-0020](0020-safe-local-autosave.md) 在已实现的手动草稿基础上增加**用户按需开启**、工程内容防抖保存和跨标签页冲突停写。此处保留第十一批首次实施时“不自动保存”的历史决策背景；第十二批的自动保存能力仍需单独质量与人工验收。
