# ADui SCADA · V1 软件需求规格（草案）

> 状态：**V1 规划基线**。需求项尚未实现；具体协议支持深度、性能容量和现场交付条件仍待确认。

## 1. 产品定位、目标与边界

工业 SCADA / HMI 平台，覆盖工程创建 → 设备与 Tag 配置 → 2D 组态编辑 → 校验发布 → 运行监控 → 报警/历史追溯。Vue 3 与 React 两个正式 Web 版本，共享一套 Schema、核心引擎、后台及工业采集网关。

V1 目标：SVG 组态编辑器、独立 Runtime、工程版本发布、OPC UA/Modbus TCP/MQTT 只读采集路径、Tag 质量、报警、历史、RBAC、私有化部署准备；Windows Tauri 可以阶段性交付。3D 编辑器、Cesium GIS、Flutter、原生移动 App、通用 PLC 写入和严格 HA 不作为 V1 必交付项。

## 2. 角色与场景

| 角色         | 典型职责                       |
| ------------ | ------------------------------ |
| 平台管理员   | 用户角色、网关与平台配置       |
| 工程设计人员 | 工程、数据源、Tag、组态、发布  |
| 运行值守人员 | 监控、趋势查询、按权限确认报警 |
| 只读访客     | 查看授权工程和页面             |

样板：水处理监控。工程师编辑水泵、水箱、管线；模拟设备产生液位/运行状态；两个框架读取同一工程；断线时显示坏质量；报警记录可追溯。

## 5. MVP、验收与变更

第一闭环：`FR-002` → `FR-004`（模拟数据）→ `FR-005`/`FR-006` → `FR-007` → `FR-009` → `FR-013`。之后接工业网关、报警、历史、安全。

## 6. 待确认事项

## V0.2 第十一批：浏览器本地工程草稿（FR-002 局部）

两套 Studio 增加按 `projectId` 隔离的**手动保存、恢复和清除**浏览器本地草稿，均使用共享 Core 的存储校验契约。覆盖已有草稿、恢复替换现有画面及清除草稿需确认；损坏、超限和不兼容记录拒绝恢复，保留当前工程。该功能仅覆盖 FR-002 中的**本地单工程草稿**子集，**不意味着多工程管理、服务端保存、权限控制或正式发布已实现**。跨 Origin 的 Vue/React 浏览器存储不自动同步，双框架的工程交换仍使用受校验的 JSON。详见 [ADR-0019](adr/0019-local-draft-persistence.md)。

## V0.2 第十二批：按需自动保存与恢复提示（FR-002 / NFR-006 局部）

在已实现的浏览器手动草稿基础上，Vue 与 React 新增**按需开启**的自动保存：仅在工程内容改变并连续闲置约 1 秒后更新同一 `projectId` 的本地记录。已有草稿需要确认后才允许后续自动覆盖；默认关闭、不自动恢复。不同标签页修改或删除同一存储键时暂停自动写入，损坏/不兼容记录不可自动覆盖。该功能只属于**浏览器临时草稿**，不包含正式服务器工程管理、可靠并发事务、发布或权限。详见 [ADR-0020](adr/0020-safe-local-autosave.md)。

## V0.2 第十二批存储方案调整：IndexedDB 与 Dexie.js

本批按维护者要求，将当前 Vue/React 浏览器工程草稿的正式实现改为 **IndexedDB**，使用经核对的 `dexie@4.4.7`。工程 Schema、人工恢复确认与按需自动保存规则不变；存储接口改为异步 `DraftRepository`，同一工程版本检查与写入在单个 IndexedDB 事务中完成。已有合法 `localStorage` 草稿只能经受控校验迁移，确认数据库事务提交成功后才删除旧备份，防止无声丢失；浏览器存储仍不是正式服务端持久化或工程发布。详见 [ADR-0021](adr/0021-indexeddb-dexie-storage.md)。

## V0.2 第十三批：模拟 Tag 绑定编辑（FR-006 局部）

Vue/React Studio 支持单选且未组合图元的模拟 Tag 选择或清除：水箱使用 `level`，水泵使用 `running`，文本使用 `value`，管道暂不支持。通过共享 `DocumentEditor.setSelectedBinding` 保证校验、原子提交、撤销重做与工程 JSON 互通；原有 IndexedDB 草稿保存协议不变。

下拉候选仅包含 `water.level`、`water.pump.running`、`water.flow` 等已存在的本地演示 Tag。其他已导入的合法绑定不会被自动删除。此阶段不包含正式 Tag 配置管理、数据源/地址映射、真实工业网关和设备写入，FR-006 尚未全部交付。

## V0.2 第十四批：本地多页面工程管理（FR-002 / FR-005 局部）

Vue/React Studio 支持在同一 `ScadaDocument 0.2.0` 工程内创建、重命名、切换和删除页面；新页继承当前画布尺寸，初始为空，最多 100 页，至少保留 1 页。当前页面是框架无关 `DocumentEditor` 会话状态，切换时清除选中状态和拖动预览，但不改动工程 JSON 或自动保存基线。页面创建、重命名、删除与图元操作可以撤销、重做，删除后仍可在当前编辑会话内撤销恢复原图元及 Tag 绑定。

画布移动、吸附、框选、几何、组合及模拟 Tag 绑定必须作用于当前页面，工程级图元 ID 与组合 ID 仍保持唯一。JSON 导入导出和 Dexie 草稿保存整份工程，成功导入后默认选第一页。只读 Runtime 的默认第一页渲染保持不变。本阶段仍不包括多工程后台、服务端持久化、发布、权限、真实设备写入。详见 [ADR-0022](adr/0022-multi-page-editor-scope.md)。

## V0.2 第十五批：页面复制、排序与跨页面图元复制（FR-002 / FR-005 / FR-006 局部）

Vue/React Studio 提供复制当前页面、页面前移/后移、将当前页选中的图元复制到其他页面。复制页面时保留尺寸、布局、属性、规则和 Tag 绑定，但重新分配页面、图元和组合 ID；复制出的页面紧邻原页面。页面排序只调整 `pages[]` 的顺序，保留 ID，并可以撤销/重做。

跨页面图元复制不移动或删除来源内容，会自动携带选中组合的全部成员，为目标页生成新图元和新组 ID；在目标画布可容纳时整体平移，无法容纳时明确拒绝。合法操作使用共享 `DocumentEditor` 命令和当前 Schema `0.2.0` 的原子校验，沿用 IndexedDB 草稿与 JSON 双框架互通。默认 Runtime 仍展示 `pages[0]`，因此页面排序会影响默认运行时页面。完整说明见 [ADR-0023](adr/0023-page-copy-and-reordering.md)。

本阶段不实现跨工程剪贴板、图元剪切/粘贴、页面启动路由配置、服务端保存/发布或真实工业设备写入。

## V0.2 第十六批：Studio 图元会话剪贴板（FR-005 / FR-006 / FR-013 局部）

Vue/React Studio 增加「复制所选」「剪切所选」「粘贴图元」以及 `Ctrl/Cmd+C`、`Ctrl/Cmd+X`、`Ctrl/Cmd+V`。操作通过共享 `DocumentEditor` 实现：复制不修改工程、不产生撤销历史；剪切与粘贴各形成一条可撤销命令；选中组合成员时自动包含整组，并在粘贴后重新生成全工程唯一的图元及组合 ID，保留 Tag、规则、属性与几何。粘贴尝试每次递增 20 像素偏移，靠近画布边界时整体限制位移，空间不足则拒绝且不污染文档。

剪贴板仅存活于当前编辑会话，不访问系统剪贴板、不保存到工程 JSON/IndexedDB；切换页面允许粘贴到其他页面，导入或恢复工程后清空。文本输入控件中的浏览器默认快捷键仍然有效。工程 Schema `0.2.0`、只读 Runtime、Dexie 草稿安全策略不变。详见 [ADR-0024](adr/0024-session-node-clipboard.md)。

不包含跨 Origin / 跨应用剪贴板数据格式、粘贴外部 SVG/HTML、设备通信或写入权限。

## V0.2 第十七批：图元锁定、显示隐藏和批量图层状态（FR-005 / FR-006 / FR-007 局部）

共享 Core 为 SVG 图元提供持久化的编辑器锁定与可见性状态。Vue/React Studio 支持对单个或多个选中图元执行锁定、解锁、隐藏和显示；隐藏图元仍在图层列表中，可选中恢复。锁定阻止拖动、几何、组合、编辑绑定、剪切、删除、复制选中、图层排序等误操作，必须显式解锁。

为避免改变 `ScadaDocument 0.2.0` 顶层字段和破坏旧版白名单工程结构，状态存放在已有 `node.props.__scadaStudio`，仅允许 `locked`、`visible` 两个可选布尔字段。Runtime 将隐藏图元从 SVG 中移除，锁定图元仍正常显示。批量变更各为一条可撤销命令，沿用 JSON 与 Dexie IndexedDB 草稿事务。

**兼容限制：** 旧版 Runtime 不识别 `visible: false`，含隐藏图元的工程不得在旧版 Runtime 中使用；正式发布需要后续引入能力校验或版本协商。本批锁定只防误操作，不属于用户权限、PLC/DCS 设备授权或安全认证。详见 [ADR-0025](adr/0025-node-lock-visibility.md)。

## V0.2 第十八批：图元精确图层排序及面板优化（FR-005 / FR-006 / FR-013 局部）

Vue/React Studio 图层面板改为最上层在顶部，提供拖放位置指示和非拖拽的「目标图元、上方/下方、移动到指定层」操作。共享 `DocumentEditor.moveLayer` 在当前页按目标图元位置进行原子插入：源属于组合时整组成员连续移动，目标属于组合时以整组首/末成员为边界。既有四个排序按钮对纯组合选中也使用同一连续移动语义，保留普通多选原操作。

无变化不写撤销历史；发生变化时可撤销重做，保持工程 Schema `0.2.0`、Tag、几何、组 ID、规则、隐藏状态与 Dexie IndexedDB 草稿不变。锁定图元及含锁定成员的组合不得移动，若间接改变已锁定图元的原始层序同样拒绝。支持跨 Vue/React 的完整 JSON 往返，具体见 [ADR-0026](adr/0026-precise-layer-order.md)。

本批不提供跨页面拖放、外部资源拖入、设备写入、正式工程发布或泛化图层树。

## V0.2 第十九批：组合图层树、搜索和选中定位（FR-005 / FR-006 / FR-013 局部）

Vue/React Studio 的图层面板增加一层平面组合树：同一 `groupId` 的图元以可折叠组合标题和成员子行呈现，视觉上层显示在顶部；可按图元 ID、图元类型、文本和组合 ID 搜索，匹配成员时保留所属组标题并临时展开。点击组标题或成员继续使用共享 `DocumentEditor.select` 的整组选择与 Shift 多选语义，画布选中会同步展开所属组。「定位选中图层」能清除过滤、展开所属组并滚动到图层面板中的对应行。

树结构由共享 `buildLayerTree` 从当前页 `nodes[]` 动态派生，搜索和折叠只在 UI 会话中，不写工程 JSON、IndexedDB 或撤销历史。旧工程中成员非连续的组合标记「层序不连续」，不会因为展示树自动重排；拖动仍调用原精确排序命令并保护锁定组。保留 Schema `0.2.0`、Tag、几何、Runtime 及双框架工程互通。详见 [ADR-0027](adr/0027-layer-group-tree-projection.md)。

本批不包含真实的嵌套组合、持久化组文件夹、独立图层名称、搜索结果在画布自动居中或工业设备控制。

## V0.2 第二十批：双框架 TDesign 组件选型与属性面板基础迁移（FR-005 / FR-006 / FR-013 局部）

维护者确认 React 端统一使用 `tdesign-react` + `tdesign-icons-react`，Vue 3 端统一使用 `tdesign-vue-next` + `tdesign-icons-vue-next`。两套 UI 组件库在当前工程中逐步替换现有原生控件，依赖版本由根 pnpm Catalog 管理，不新增 Ant Design。首先迁移 Studio 右侧属性操作按钮、显示文案输入和左侧图层搜索输入与清除图标，保留此前所有共享 Core 编辑命令、锁定/隐藏、撤销/重做、IndexedDB 草稿和 SVG Runtime。

`GEOMETRY_PROPERTY_FIELDS` 统一放在共享 Core，为 React/Vue 几何属性表单提供完全相同的字段与中文标签。现阶段几何输入与 Tag 下拉继续使用原有受验证表单逻辑；颜色、边框、透明度须待工业 Tag 质量显示语义和共享 SVG 白名单定稿后再实现，不得把未完成能力写成已实现。设计与安装边界见 [ADR-0028](adr/0028-tdesign-dual-framework-ui.md)。

本批依赖需要维护者在联网 Windows 先更新并提交锁文件，方可执行冻结锁文件安装和完整 `pnpm run ready`。

## V0.3 第二批：工程校验结果与快照基础（FR-008 前置工作）

共享 Core 增加 `validateProjectDocument`、`createProjectSnapshot`、`readProjectSnapshot`：沿用现有 `ScadaDocument 0.2.0` 严格校验，返回首错结构化结果；构建独立深冻结工程副本，并以涵盖修订号、创建时间和完整工程数据的 SHA-256 摘要校验跨 JSON 往返的完整性。无效工程、版本、摘要、时间与超限记录均拒绝，失败不修改任何现有工程状态。

这仅交付 **FR-008 前置 Core 数据契约**；尚未形成正式发布（权限、审计、版本仓储、原子发布指针、Runtime 发布态加载、回滚），FR-008 表格状态保持“规划中”。快照摘要不是身份认证或可信数字签名。详见 [ADR-0035](adr/0035-project-validation-snapshot.md)。

## V0.3 第三批：本地工程历史版本仓储（FR-002 / FR-008 前置工作）

在已实现的结构化工程校验及不可变快照基础上，新增框架无关版本仓储接口和独立 Dexie 本地 IndexedDB 适配：按工程分配从 1 起的递增修订号，每次只追加快照；不同页面并发更新必须携带 `expectedRevision` 并在同一数据库事务里严格比较，过期写入拒绝；提供版本详情及倒序分页摘要查询，读取时必须再次校验 SHA-256。

这是 **FR-002 本地历史管理能力与 FR-008 的前置数据契约**，不是正式服务端版本仓库、已发布版本、回滚、RBAC 或审计。正式 FR-008 的状态仍维持“规划中”。现有 Dexie 草稿库及 Vue/React 运行画面不变，见 [ADR-0036](adr/0036-local-version-history.md)。

## V0.3 第四批：Vue/React 本地版本历史界面（FR-002 / FR-013 局部）

两套 Studio 新增“版本历史”菜单，可为当前本地工程创建只追加快照、按修订号倒序分页查询、查看与当前画面的页面/图元/Tag 绑定数量及内容是否一致，并在**明确确认**后将历史工程载入当前编辑会话。取消载入不修改当前工程或自动保存状态；确认后暂停并等待草稿自动保存，重置编辑器临时状态与撤销历史，但**不自动覆盖 IndexedDB 草稿，也不进行正式工程发布**。历史记录按 Origin 隔离，Vue/React 不共享浏览器本地历史，跨框架仍使用受校验的 JSON。FR-008 发布/回滚继续处于规划中。详见 [ADR-0037](adr/0037-studio-version-history-ui.md)。

## V0.3 第五批：本地历史恢复安全回归（FR-002 / FR-013 / FR-016 局部）

对已实现的 Vue/React 历史版本载入补齐一致性保护：JSON 导入从异步读取开始占用工程操作门闩，历史载入不能插入；确认载入前停止自动保存并等待已提交的写入结束，取消保留原工程与自动保存；载入不能暗中覆盖现有 IndexedDB 草稿。新增自动化模拟刷新后历史恢复、不同 Origin 隔离与浏览器存储权限异常，确保故障时保留画面。**不扩展正式发布、服务器仓储或工业写入能力。** 见 [ADR-0038](adr/0038-version-recovery-safety.md)。
