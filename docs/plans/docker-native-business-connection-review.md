## 1. 已验收事实和当前限制

维护者真实 Windows Docker 原生临时表事务已经通过：提交、主动回滚恢复原值、同一后端、临时表清理及连接关闭；没有写入正式业务表。常驻只读、Discovery/JWKS 和七服务回归退出码 0。详见 [验收记录](../VALIDATION.md)。

当前代码有三条连接边界：

| 连接 | 目标 | 当前限制 |
| --- | --- | --- |
| 宿主原生连接 | 127.0.0.1:15432/adui_scada | 固定非生产连接入口 |
| 容器常驻连接 | postgres:5432/adui_scada | docker-readonly、严格只读、无 OIDC/工程 API |
| 容器独立临时事务 | postgres:5432/adui_scada | docker-transaction-probe、显式确认、单连接池 |

[Compose](../../deploy/docker/compose.yaml) 将 PostgreSQL POSTGRES_USER 与 Keycloak KC_DB_USERNAME 都设置为 adui_scada，并使用同一随机数据库密码。Keycloak 独立逻辑库的初始 SQL 仅创建数据库。固定原生运行时边界同样要求当前角色、会话角色均为 adui_scada。当前角色及两个数据库的实际所有权、角色属性、有效权限和 PUBLIC 权限尚未通过本次真实目录核验；配置中的共享身份不是数据库级最小权限证据。default_transaction_read_only 是连接模式，不等于角色无写权限。

[原生数据库模块](../../apps/server/src/database/prisma8-database.module.ts) 对不属于现有只读模式的 production 连接明确拒绝；[启动入口](../../apps/server/src/main.ts) 保持常驻只读与 OIDC 根模块独立；[Nginx 配置](../../deploy/docker/nginx.conf) 只转发 /api/health，其他 /api/ 请求返回 404。不得通过移除这些门禁提前启用业务写入。

## 2. 建议的安全边界（待确认）

保持单一 adui-scada Compose 项目、七服务、一个 PostgreSQL 实例、现有两个逻辑库及现有数据卷。角色拆分是当前新库自身的安全建设，不是旧库接管或历史数据迁移。

| 角色职责 | 建议边界 |
| --- | --- |
| 安装与管理身份 | 保留受控管理用途；不作为正式常驻应用或 Keycloak 的连接凭据 |
| SCADA 运行身份 | 建议独立登录角色 adui_scada_runtime，仅访问 adui_scada；按实际仓储 SQL 授予必要表/列/序列权限，不具备任意 DDL、角色管理、跨库访问或发布写入特权 |
| Keycloak 运行身份 | 建议独立登录角色 adui_scada_keycloak_runtime，仅访问 adui_scada_keycloak；其当前版本实际启动与自身 Schema 演进所需权限必须独立确认，不授予业务库权限 |

角色名称、权限矩阵和身份切换方案为建议，需核对当前真实目录后评审。运行身份不得拥有 SUPERUSER、CREATEDB、CREATEROLE、REPLICATION、BYPASSRLS 或可继承/切换到管理角色的成员关系；禁止拥有业务表、业务 Schema 或数据库而获得隐含管理能力。跨库拒绝必须核验有效 CONNECT 权限、PUBLIC 及成员关系，而非仅检查显式 GRANT。Keycloak 既有对象所有权与 Schema 管理要求单独评审，不自动迁移所有权或回收 PUBLIC 权限。

当前原生身份核验使用 pg_catalog.pg_control_system()、prisma_contract.marker 和固定角色等条件。新运行身份须保留真实集群、库、角色、Schema、PG19、存储指纹和事务模式校验；优先评估必要的精确只读权限，不通过授予超级用户或通用监控角色绕过。不改变原生契约与业务表结构、索引、中文注释或发布安全门禁。

未来应用凭据必须独立随机生成、仅通过精确的本机秘密文件绑定交付，禁止把管理密码、Keycloak 管理密码、根私钥或其他秘密目录挂入 SCADA 服务；禁止写入 Git、镜像、命令行、诊断和前端。既有绑定仍保留，不自动覆盖、轮换或切换运行身份。

## 3. 分阶段实施与验收

### A. 当前新库角色只读预检（下一批代码候选）

- 拟新增独立宿主只读预检入口，复用已有本机 Docker Desktop、固定业务库、严格原生契约及集群核验，不进入 docker:up 或 ready 的真实数据库步骤。
- 只执行固定目录查询，核对业务库及 Keycloak 库的所有者、既有登录角色属性、直接/间接成员关系与有效 CONNECT 权限、业务 Schema CREATE/USAGE、现有自有业务表/序列所有权与操作权限、标记和集群身份函数访问条件。对 Keycloak Schema 的实际权限核对使用严格只读的独立连接，不从业务库查询冒充已验证其对象。
- 仅输出必要的固定状态和最小权限矩阵，不显示连接串、口令、业务行、外部身份或无关角色名。若发现权限过宽，区分目录核查成功与角色准入不通过；拒绝将无法读取目录、缺字段或未知权限伪装为安全。
- 拒绝非本机、旧项目、非预期数据库/集群、额外命令参数和非严格只读事务。无 CREATE ROLE、ALTER、GRANT、REVOKE、业务 DML、DDL、初始化、迁移、清库或卷操作。默认应用及现有只读探针保持不变。
- 离线测试覆盖共享管理身份、过宽有效权限、跨库、继承或 SET ROLE、缺少必要只读权限、目录异常、报告不完整和脱敏；真实预检仅由维护者在当前新库执行，结果作为 B 阶段权限设计输入。

### B. 独立运行角色配置候选（单独审批）

根据 A 阶段真实目录和当前仓储语句形成准确权限矩阵、受控 SQL、变更前核验、非破坏性失败处置及经授权的回退方案。明确 Keycloak 启动及已有数据所有权的影响。未经维护者明确确认，不创建或修改角色、授权、密码、库所有权及现有对象权限；不执行旧数据迁移、不重新初始化数据库。执行后必须核验原生存储指纹不变，分别证明正向最小访问及负向跨库、DDL、管理权限拒绝，不能以模拟代替。

### C. 正式本机业务连接候选（单独审批）

仅在 B 阶段验收后提出独立显式启用的容器业务模式。复用唯一 Prisma8Service、既有正式事务边界和 OIDC/工程根模块；不得复用 docker-transaction-probe 作为常驻写模式，不允许任意 URL、回退到管理角色或通用 production 放行。默认 docker:up 继续只读，默认关闭 OIDC；模式冲突、绑定不匹配、角色或集群漂移时拒绝启动及关闭资源。健康检查报告实际模式，不公开内部数据库探针。是否需要独立启动命令及具体配置名后续随代码评审确定。

### D. OIDC 和双端真实联调（单独审批）

只允许固定本机 HTTPS 同源代理、固定 Issuer、可信 CA、显式授权码/PKCE/JWS 校验及现有外部身份预绑定。明文 HTTP 仍不得公开认证/工程 API；React/Vue 的回调、Cookie 作用域、CSRF、Origin 和跨端会话语义需独立审查，不假定不同端口等同不同 Cookie 作用域。真实身份创建/绑定与工程写入夹具逐项授权，验证会话撤销、租户/ACL 拒绝、工程 CAS 与版本事务、双端互通；禁止打开正式发布/回滚门禁或设备控制。未完成现场安全评审不得声称达到生产部署资格。

## 4. 本次交付及待决策

本次 PR 仅提交安全评审文档，不修改源码、Compose、环境变量、数据库、角色、凭据、依赖、接口或运行容器。维护者评审后先实施 A 阶段只读核查，只有确认真实权限矩阵并单独授权 B 阶段后，才能执行任何角色和权限变更。C、D 继续按独立小批次验收。

拟请维护者确认：保持现有七服务及一个 PostgreSQL 实例，采用管理、SCADA、Keycloak 三类身份隔离方向；允许下一批实现只读角色核查，暂不授权角色变更、数据库写入、OIDC 或工程接口启用。
